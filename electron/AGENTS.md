# Desktop (Electron)

The desktop app is an Electron shell around the Vite app. `bun run dev:desktop` runs it on the dev server (`KALKA_DEV_URL`), `bun run package:desktop` builds the DMG and ZIP on macOS, an NSIS installer on Windows and an AppImage on Linux with electron-builder; `bun run --cwd electron build` bundles the main process, preload and MCP server.

- The renderer reaches the desktop only through the preload bridge (`electron/src/preload.ts`) and the IPC handlers registered in `electron/src/handlers/index.ts`; app code calls them through the `@tauri-apps/*` modules that `vite/aliases.ts` maps to `src/app/platform/tauri`. A new native capability is a handler plus its `src/app/platform/tauri` counterpart.
- The app page loads from the `kalka-app://` protocol with a strict CSP (`electron/src/main.ts`); keep remote content out of the editor window.
- The editor window has no native title bar: the tab bar is the title bar, a `-webkit-app-region: drag` area whose tabs and buttons are `no-drag`, padded clear of the window controls with the Window Controls Overlay's `titlebar-area-*` CSS variables (`title-bar` in `src/app.css`); window options and caption-button colors live in `electron/src/handlers/title-bar.ts`, kept in the app's theme through Tauri's `setTheme` (`src/app/shell/window-theme.ts`, `electron/tests/title-bar.test.ts`). Windows without a tab bar, such as Software Update, keep the native frame.
- Closing the window or quitting asks the editor, which acknowledges at once (`window.acknowledgeClose`) and asks about unsaved documents in its own dialog; only a page that crashed or does not acknowledge within `PAGE_ANSWER_TIMEOUT_MS` gets the native box, worded in the language the page last set (`electron/src/handlers/close-ask.ts`, `electron/tests/close-ask.test.ts`).
- Secrets are encrypted with `safeStorage` and stored as ciphertext only (`electron/src/handlers/credentials.ts`); failures must surface, never fall back to plaintext (`src/AGENTS.md`, Settings).
- Child processes follow the command scopes in `electron/capabilities/shell.json` (`electron/src/handlers/shell.ts`); a scope pins the whole command line, no free arguments.
- The MCP server ships inside the app: `electron/scripts/build-mcp.ts` bundles `packages/mcp` into `electron/dist/mcp`, which runs with `ELECTRON_RUN_AS_NODE` (`electron/src/handlers/mcp/bundled.ts`); one-click client setup lives in `electron/src/handlers/mcp/clients.ts`, CLI runs (Windows `.cmd` shims through `cmd.exe`) and the file fallback in `cli.ts` and `connect.ts` beside it, failures reported as codes the page translates, with client paths and comment-preserving JSONC/TOML edits in `electron/src/handlers/mcp/config/` (`electron/tests/mcp-config.test.ts`); the same script packs the stdio bridge as `dist/mcp/kalka.mcpb` for Claude Desktop (`electron/scripts/mcp-bundle.ts`).
- CLIs are looked up on the login shell's `PATH`, read once with `env -0` between markers (`electron/src/handlers/login-env.ts`); desktop-only tests live in `electron/tests/` (shard `desktop`) and use temporary homes, never the user's configuration.
- The native menu is built from `electron/generated/menu.json`, produced by `bun run generate:tauri-menu` from `src/app/shell/menu/schema.ts`; do not edit it by hand.
- PNG and JPG exports and `.fig` thumbnails are captured from an offscreen window and PDF exports printed from it (`electron/src/handlers/raster.ts`, commands `render_html_image` and `render_html_pdf`, called by `src/app/document/export/dom-raster.ts`); the same code is the render host of the CLI and the unit tests, `electron/src/render-host.ts`, an Electron process that shows no window, lives as long as the process that started it and answers JSON lines on stdin, drawing pages as PNG, JPG or PDF (`printToPDF`) and running the CLI's layout script in an offline page; `bun run --cwd electron build:render-host` builds it alone; `.fig` files are compressed with Node's zstd (`electron/src/handlers/fig.ts`).
- Files, `.kalka` archives, Kalka folders and `kalka://` links arrive through `electron/src/handlers/pending.ts`, from the command line, a second launch or the Finder.
- Updates come from the `publish` feed in `electron/package.json` through `electron-updater` (`electron/src/handlers/updater.ts`), behind the Software Update window's Tauri-shaped calls (`src/app/platform/tauri/plugin/updater.ts`); a downloaded update installs on restart, or at once on Windows.
- `bun run --cwd electron smoke` starts the app `package:dir` built, with its own profile, and waits for the editor; CI runs it on macOS, Windows and Linux (under `xvfb-run`) before packaging (`.github/workflows/desktop.yml`). macOS builds sign and notarize when the Apple secrets exist, with the JIT entitlements in `electron/build/entitlements.mac.plist`.
- The development app at `electron/.dev/` holds a single-instance lock and port 7600 like an installed one; drive a second copy with its own `--user-data-dir` and `--remote-debugging-port`.
- The macOS installer window's background is `electron/build/background.tiff`, a 1×/2× TIFF rendered from `electron/scripts/dmg/background.html` by `bun electron/scripts/dmg/render.ts` on a Mac; edit the HTML and re-render, and keep the icon centres in `build.dmg.contents` (`electron/package.json`) where the HTML draws their wells. electron-builder sizes the window from the image and Finder's title bar takes its last 28 px, so the image is 660×448 with nothing drawn below 420.
- macOS builds without an Apple certificate are signed ad hoc as a whole by `electron/scripts/adhoc-sign.cjs` (`afterPack`); without it a downloaded copy is reported as damaged on Apple Silicon.
